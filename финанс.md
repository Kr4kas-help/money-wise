# финанс.md — инструкции по проекту «Из долгов — к мечте»

Мини-продукт, который помогает человеку разобраться с деньгами: понять, сколько отдавать на долги, сколько откладывать и когда исполнится задуманное. Сайт спрашивает о доходе, семье, долгах и желаниях, затем считает индивидуальный план в рублях и процентах.

Продакшен: https://money-wise-tau.vercel.app
Проект Vercel: `money-wise`, команда `kr4kas-helps-projects`, регион iad1.

---

## 1. Стек и запуск

- Next.js 14.2.15, App Router, React 18.3.1.
- TypeScript 5.5.4, строгая типизация.
- Tailwind CSS 3.4.13, свой набор цветов в `tailwind.config.ts`.
- Шрифты через `next/font/google`: Literata (заголовки) и Onest (текст), оба с кириллицей.
- Хранилища на сервере нет. Данные пользователя живут только в браузере.
- Деплой: `npm run build` на Vercel, статические страницы плюс серверные обёртки.

Команды:

```
npm install
npm run dev      # локальная разработка
npm run build    # проверка типов и сборка
```

Важно: в песочнице Cowork реестр npm заблокирован, локальная сборка там невозможна. Проверка идёт сборкой на Vercel: деплой → `get_deployment` → `list_deployment_events`.

## 3. Данные

`Profile` — единственный источник правды, хранится в контексте:

```ts
ageGroup: 'young' | 'adult' | 'senior' | null
family: 'single' | 'couple' | 'family' | 'single_parent' | null
source: 'salary' | 'pension' | 'business' | 'other' | null
incomeType: 'stable' | 'flexible' | null
problems: Problem[]      // множественный выбор, шаг 3
goals: Goal[]            // множественный выбор, шаг 4
income: number           // доход в месяц, руб.
partnerIncome: number    // зарплата партнёра, показывается при family = couple | family
mandatory: number        // обязательные расходы без долгов
debts: Debt[]            // kind, name, balance, monthly, rate
wishes: Wish[]           // name, cost, months | null
largeText: boolean       // крупный режим для пожилых
step: number             // 0..7
```

`totalIncome(profile)` — общий доход: `income + partnerIncome`. Использовать везде, где нужен доход. Внутри `buildPlan` создаётся копия `q` с общим доходом, и вся математика идёт по ней.

## 4. Правила расчёта

**Свободные деньги.** `доход − обязательные расходы − платежи по долгам`. Если ноль или минус, план не строится: возвращается `ok: false` с рекомендациями, а желания всё равно разбираются.

**Веса распределения** (нормируются, поэтому сумма не обязана быть 1):

- база: долги 0.6, подушка 0.15, желания 0.25, рост 0.2;
- если цель `debt_free` или целей нет — доля долгов 0.6, иначе 0.4;
- `debts` в проблемах: +0.1 к долгам;
- `no_money`, `no_saving`: +0.1 к подушке; `no_plan`: +0.05;
- `impulse`: −0.1 к желаниям, но не ниже 0.1;
- гибкий доход: +0.1 к подушке;
- рост включается только при цели `grow`.

**Долги.** Ежемесячные проценты `balance * rate / 1200`, затем минимальный платёж, затем досрочное погашение по убыванию ставки. Остаток от досрочного, если долг закрылся, уходит в подушку. Расчёт до 360 месяцев.

**Желания.** Копятся в общем порядке сортировки по желаемому сроку (без срока — в конце). Сложный процент на накопления: 8% годовых, ставка условная.

**Разбор желаний** (`analyzeWishes`). Для каждого желания строится план без него и сравнивается с базовым. Вердикты:

- `drop` / «Лишняя» — не накопить за 30 лет, или без неё долги закрылись бы, или она отодвигает долги на 2+ месяца;
- `postpone` / «Отложить» — срок сдвигается;
- `keep` / «Можно оставить» — укладывается.

Причина всегда конкретная: называется желание, сумма и сдвиг в месяцах.

**Модель распределения** (`pickModel`), первое подходящее совпадение: антикризисная → лавина (долги) → запас на нестабильный доход → рост денег → спокойная (пожилые) → классика 70/20/10.

## 5. Правила интерфейса

**Анкета.** Шаги 0–7, на каждом кнопка «Дальше» блокируется, пока нет ответа. Проблемы и цели выбираются множественно. Шаг 3 требует хотя бы одну проблему, шаг 4 — хотя бы одну цель, шаг 5 — доход больше нуля.

**Режим для пожилых.** Выбор «60 лет и старше» включает `largeText`, а он ставит `data-size="large"` на `<html>`. Все размеры шрифтов, кнопок и отступов заданы CSS-переменными в `globals.css` — новые элементы должны использовать `var(--fs-base)`, `var(--fs-small)`, `var(--tap)`, а не фиксированные `text-base` и высоты.

**Кнопки.** Базовый класс `.btn` плюс один из вариантов:

- `.btn-primary` — основное действие, ель;
- `.btn-ghost` — второстепенное;
- `.btn-gold` — «Золотые правила» (золотая заливка, тёмная кайма);
- `.btn-white` — «Крупный шрифт» (белая заливка, чёрный текст).

**План.** Переключатель «Строки/Таблица» управляет и распределением, и помесячным планом. В таблицах обязательны `overflow-x-auto`, `<caption class="sr-only">` и `scope="col"`.

**Цитаты.** В шапке цитата меняется каждые 40 секунд (`ROTATE_MS = 40000`). На странице плана внизу одна цитата дня через `quoteOfDay()`.

**Предупреждение.** `WarningModal` открывается при первом заходе сессии, блокирует прокрутку и закрывается только после галочки. Факт ознакомления хранится в `sessionStorage` под ключом `money-wise:warning-ack`.

## 6. Состояние и хранение

`lib/store.tsx` — единственное место работы с хранилищем.

- Обычный режим: `localStorage`, ключ `money-wise:v1`, чтение один раз при загрузке, запись при каждом изменении после `ready`.
- Миграция: старое поле `problem` превращается в массив `problems`.
- Демо-режим `FRESH_START = true` (сейчас включён по просьбе владельца): прошлые данные стираются при заходе, запись не идёт, каждый визит начинается с нуля. Когда понадобится вернуть сохранение — поставить `false`; текст `CacheNote` и `WarningModal` переключится сам.

Добавляя поле в `Profile`, обязательно добавь его в `emptyProfile` — иначе старые сохранения дадут `undefined`.

## 7. Дизайн

- Палитра: `paper #EEF1E8`, `ink #23302B`, `spruce #2F6F5E`, `honey #E0A526`, `rose #B5544A`, `mist #DDE5D8`.

- Долги помечаются розовым, накопления елью, цель медовым.
- Уважать `prefers-reduced-motion`: анимации не обязательны для понимания.

## 8. Правила правок

1. Математику менять только в `lib/plan.ts` и `lib/models.ts`. Компоненты не считают деньги сами.
2. Любой доход считать через `totalIncome(profile)`, а не `profile.income`.
3. Тексты рекомендаций пишутся в интерфейсе, а не в голове пользователя: конкретное желание, сумма, срок.
4. Новое поле профиля — это правка четырёх мест: `types.ts`, `emptyProfile`, шаг анкеты, расчёт.
5. После правки — деплой на Vercel и проверка `readyState: READY`. Локальная сборка недоступна.
6. Не выводить на сервер персональные данные. Сайт не просит номера счетов и карт, и не должен.
7. Расчёты учебные, а не финансовая консультация. Эта оговорка обязательна в предупреждении и в подвале плана.

## 9. Открытые вопросы

- Модель распределения (`pickModel`) и расчёт плана (`buildPlan`) живут отдельно: проценты в карточке модели и доли рублёвого плана считаются по разным весам и могут слегка расходиться. Свести их в один источник — отдельная задача.
- Версия Next.js 14.2.15 имеет известную уязвимость, стоит обновить до исправленной.
- Защита Vercel Authentication включена по умолчанию: публичный доступ требует отключить её в Settings → Deployment Protection.
- Доходность накоплений 8% годовых взята условно, в тексте это сказано, но стоит вынести в настройку.
